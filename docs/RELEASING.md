# Releasing

JustCode's installers are built and published by
[`.github/workflows/release.yml`](../.github/workflows/release.yml). It runs
on GitHub-hosted runners and produces:

| Platform | Artifacts |
| --- | --- |
| Windows | `.exe` (NSIS) and `.msi` (WiX) |
| Linux (`ubuntu-22.04`) | `.deb` and `.AppImage` |
| macOS | a universal `.app` / `.dmg` (Apple Silicon + Intel in one binary) |

All artifacts are uploaded to a single GitHub Release named after the tag
that triggered the build.

## Prerequisites

- The repo is pushed to GitHub with Actions enabled.
- Nothing else — the workflow authenticates with the repo's default
  `GITHUB_TOKEN` (granted `contents: write` in the workflow file itself), so
  no secrets need to be configured to cut a release.

The installers are **unsigned**. Windows SmartScreen and macOS Gatekeeper
will both show an "unknown publisher" warning on first launch — expected for
an OSS project without a paid code-signing certificate. If that's ever
added, it plugs into the same workflow via `tauri-apps/tauri-action`'s
signing inputs; nothing else here changes.

## Cutting a release

1. Bump the version in all four places that must agree — the build fails in
   confusing ways if the first three drift, and the fourth drifts silently:
   - [`package.json`](../package.json) (`version`)
   - [`src-tauri/tauri.conf.json`](../src-tauri/tauri.conf.json) (`version`)
   - [`src-tauri/Cargo.toml`](../src-tauri/Cargo.toml) (`[package].version`)
   - [`src/main.js`](../src/main.js) (`APP_VERSION`) — the fallback the About
     box shows when the Tauri API is unavailable. Nothing fails if this one is
     missed; the About box just quietly reports the previous version. It has
     been missed before, which is why it is listed here now.

   Then refresh the two lockfiles that carry the version, or the next install
   rewrites them as an unrelated diff:

   ```sh
   npm install --package-lock-only
   cargo update -p justcode --manifest-path src-tauri/Cargo.toml --offline
   ```

2. Commit that, then tag and push:

   ```sh
   git tag v0.2.0
   git push origin v0.2.0
   ```

   The tag must match `v*.*.*` — that's what the workflow's `on.push.tags`
   filter watches for. Pushing the tag is what starts the build; the release
   is published under that same tag name.

3. Watch the run under the repo's **Actions** tab. Each platform builds in
   parallel (roughly 10-20 minutes for Rust to compile from a cold cache);
   when all three finish, the release is live on the **Releases** page —
   `releaseDraft` is `false` in the workflow, so there's no manual
   "publish" step to remember.

## Testing the pipeline without cutting a real release

The workflow also has `workflow_dispatch`, runnable by hand from the Actions
tab against any branch. Use this to confirm the three builds still compile
after a dependency bump or a `tauri.conf.json` change — but know what it
actually does before relying on it:

`tagName` in the workflow is `${{ github.ref_name }}`. On a tag push that's
the tag (`v0.2.0`); on a manual dispatch it's whatever branch you ran it
against (e.g. `main`). tauri-action will happily create or overwrite a
release named after that branch, which is almost never what you want. So:

- **To smoke-test that the app builds on all three platforms:** manual
  dispatch is fine — just go cancel or delete the resulting `main` release
  afterward.
- **To test the full tag -> release path for real:** push a pre-release tag
  instead, e.g. `v0.2.0-rc1`, and delete it once you've confirmed it worked.

## Why the bundle target is `"all"`

[`src-tauri/tauri.conf.json`](../src-tauri/tauri.conf.json)'s
`bundle.targets` is set to `"all"` rather than a fixed list. Each OS then
bundles whatever formats are valid for it; the workflow narrows that further
per platform with `tauri-action`'s `args: --bundles ...` input (see the
`matrix.args` entries in the workflow file) so the exact output list above
is deterministic and doesn't depend on what happens to be installed on a
given runner image.

## App icons

Every icon the bundlers above pull from (`.ico` for NSIS/WiX, `.icns` for
macOS, the Windows Store tiles, the Android/iOS sets) is generated by
[`tools/make-icon.py`](../tools/make-icon.py) from one source mark
(`tools/justcode-mark.png`). Regenerate all of them, including the About
box's inlined copy, with:

```sh
python tools/make-icon.py
```

See the script's docstring for what each step does; there's no need to
touch `src-tauri/icons/` by hand.
